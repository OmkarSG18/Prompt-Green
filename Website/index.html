PromptGreen: Sustainable LLM Inference & Thermodynamic Optimization

PromptGreen is an academic research platform investigating shift-left prompt engineering and thermodynamic carbon modeling for Large Language Model (LLM) deployments. Developed as a final-year B.Tech Capstone Project at Dayananda Sagar University (DSU), the project addresses the invisible environmental footprint of generative AI through structural rule pruning, lexical compression, verbosity shaping, and semantic fidelity guardrails.

Technical Evaluation Dossier
Problem Statement & Motivation Thermodynamic Footprint

Modern software engineering has widely adopted foundation models across developer tools, customer service, and search pipelines. However, Transformer architecture inference incurs substantial, asymmetric computational costs:

  • Prefill Attention Complexity: Processing long input prompts requires quadratic attention operations (O(N²)), driving compute-bound GPU tensor core power draw.
  • Autoregressive Decode Footprint: Token-by-token generation is memory-bandwidth bound, reading multi-gigabyte KV caches repeatedly and consuming persistent energy per output token.
  • The Token Inflation Blind Spot: Developer prompts routinely accumulate conversational pleasantries, redundant preamble, and unconstrained outputs, silently multiplying data center energy consumption and evaporative cooling water loss.
Core Insight: Optimizing prompts before dispatch ("shifting left") reduces both input prefill compute and output decode iterations without altering downstream application logic.
Project Objectives Core Goals
1. Deterministic Token & Energy Reduction Achieve 15–35% input token compaction and curb generation verbosity to measurably lower hyperscale data center compute energy.
2. Syntactic & Semantic Invariant Safeguards Protect fenced code blocks (```), JSON schemas, LaTeX mathematical notation, and medical dosage instructions from catastrophic mutation via strict regex shielding.
3. First-Principles Thermodynamic Accounting Report energy savings in canonical Watt-hours (Wh) rather than arbitrary scores, deducting local client CPU execution overhead to prevent greenwashing.
4. Open Academic Transparency Provide full ledger auditability, exportable telemetry, and open benchmark evaluations across independent datasets.
Evolutionary Trajectory: V1 to V2 Architecture

PromptGreen evolved across two distinct research phases to solve the challenges of sustainable prompt engineering:

Version 1 (Initial Milestone): Static Pre-Deploy Gate Conceived as a CI/CD GitHub Action and diff analyzer that blocked pull requests when prompt token growth exceeded a threshold. Prompts were reviewed but never actively modified or optimized.
Version 2 (Current Research Prototype): Autonomous Active Engine Re-engineered into an active four-stage optimization pipeline combining structural rule pruning, LLMLingua-2 lexical compression, directive shaping, and neural semantic embeddings with automated atomic rollback.
Research Scope & Disclosures Academic Integrity
Prototype Status: PromptGreen is an academic capstone research prototype designed for empirical study, evaluation, and viva demonstration. It is not an enterprise commercial cloud proxy or on-die physical hardware power meter.
Energy Coefficient Modeling: Serving energy coefficients (α_prefill and α_decode in mWh) are derived from published academic literature (Luccioni et al., 2023; Patel et al., 2024; datacenter PUE 1.15) rather than real-time proprietary datacenter telemetry.
Local Compute Accounting: Optimization overhead is estimated via a conservative 35W client CPU TDP model (E_local = 35W × t_latency / 3.6e6). If local optimization energy exceeds estimated datacenter savings, the system alerts the user of a net carbon debt.

Historical Project Baseline Zero-Budget Pre-Deploy Gate Preserved in Archive

PromptGreen Version 1: Pre-Deploy Prompt Carbon Gate

The original PromptGreen V1 project established the concept of shift-left prompt review. Conceived as a zero-budget CI/CD gate and prompt diff analyzer, V1 inspected pull requests before deployment to flag high-token prompt modifications. While pioneering the concept of pre-deployment carbon awareness, V1 operated as a static reviewer without actively optimizing, compressing, or reshaping prompts.

Inspect 14-Point V1 vs. V2 Matrix
Original V1 Concept & Architecture Static Review

PromptGreen V1 investigated whether organizations could enforce carbon budgeting directly inside standard Git development workflows before deploying prompts to production.

GitHub Action Carbon Gate (promptgreen_gate.yml) Integrated as an automated pull request check (action.yml) to parse prompt diffs, count character changes, estimate token inflation, and reject PRs exceeding threshold limits.
Diff Parser & Analyzer (diff_parser.py) Evaluated modified prompts against their base version to extract added, removed, and retained lexical tokens.
Hybrid Token Inflation Predictor Combined basic regex heuristics with a Ridge / Random Forest regressor trained on a 50-pair local benchmark suite (Llama-3 8B, Mistral 7B, Phi-3 3.8B) to estimate downstream token growth.
Historical Carbon Estimation Approach Linear Lookup

V1 estimated carbon delta using a simplified linear calculation based on static token difference and flat-rate lookup tables:

ΔC = ΔTokens × (Energy_per_Token_lookup) × I_grid
Static Model Dictionary: 4 hardcoded model strings
Grid Intensity: Hardcoded regional constants (including unverified 708 gCO2e/kWh)
Methodological Limitation: The linear formula treated all tokens identically. It did not account for the fundamental asymmetry between prompt prefill attention and autoregressive decode iteration, omitted data center PUE cooling multipliers, and assumed local client computation consumed zero energy.
Documented Limitations of V1 Motivated V2
1. Passive Inspection Without Optimization: V1 could only block or approve a prompt. It placed the entire optimization burden back on developers without providing automated reduction.
2. Zero Syntactic Shielding: The diff analyzer lacked awareness of programming language grammar, JSON key-value integrity, or markdown formatting, risking syntactic breakage if prompts were altered.
3. Zero Semantic Guardrails: No vector embeddings or cosine similarity scoring existed to detect semantic drift or intent alteration.
4. Local Compute Greenwashing Risk: By ignoring the local CPU energy required for NLP parsing, small 1-token micro-prompts artificially reported positive net environmental savings.

Four-Stage Active Prompt Optimization Pipeline Thesis Chapter 5
Stage 1: Structural Rule Pruner Deterministic lexical rules and regex-based structural masking filters strip conversational boilerplate, repetitive polite honorifics, and empty greeting patterns in under 10ms.
Stage 2: Lexical Token Compressor Semantic token compaction inspired by LLMLingua. Applies adaptive perplexity thresholds and stop-word reduction with deterministic fallback.
Stage 3: Output Directive Shaper Injects concise task constraints into prompt directives to curb downstream autoregressive generation verbosity, addressing decode quadratic energy.
Stage 4: Semantic Fidelity Guard Computes sentence-transformer dense vector embeddings (all-MiniLM-L6-v2) to measure cosine similarity against original intent. Triggers automatic rollback if < threshold.
First-Principles Thermodynamic Equations (Canonical Wh) Unit-Consistent
1. E_inf_Wh = PUE × (T_in × α_prefill_mWh + T_out × α_decode_mWh) / 1000
2. E_local_opt_Wh = P_cpu_est_W × (total_latency_ms / 3,600,000)
3. ΔE_net = E_inf_orig - E_inf_opt - E_local_opt
4. ΔC_net_g = (ΔE_net_Wh / 1000) × I_grid_g_per_kWh
5. W_saved_mL = ΔE_net_Wh × WUE_mL_per_Wh (WUE = 1.8 mL/Wh)
Academic Integrity Statement: All energy values are reported in canonical Watt-hours (Wh) to avoid arbitrary unit scaling. Local CPU overhead is deducted from gross datacenter savings to ensure honest environmental accounting without greenwashing.
