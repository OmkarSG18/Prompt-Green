Section B: Unique Scientific & Engineering Contributions

PromptGreen V2 Novelty

1. Multi-Stage Active Prompt Optimization

Decouples optimization into four sequential stages: (1) Deterministic structural masking and regex pruning, (2) Lexical token compression via LLMLingua-2 with deterministic fallback, (3) Output directive shaping, and (4) Semantic fidelity guardrails.

Module: promptgreen/optimizer/pipeline.py

2. Regex-Based Structural Invariant Guard

Employs non-destructive regex structural shields that isolate code snippets, markdown tables, JSON keys, and negative medical constraints before lexical compression, guaranteeing 100% byte-for-byte preservation.

Module: promptgreen/optimizer/rule_pruner.py

3. Neural Semantic Fidelity & Auto-Rollback

Leverages sentence-transformers (`all-MiniLM-L6-v2`) to compute vector embeddings of original and candidate prompts. If cosine similarity breaches the universal threshold (≥ 0.9200), the optimizer atomically rolls back to the safe original prompt.

Module: promptgreen/optimizer/semantic_guard.py

4. First-Principles Thermodynamic Modeling

Replaces simplistic mJ token multipliers with physical Watt-hour equations modeling prefill mWh, decode mWh, datacenter PUE, and empirical WUE water impact, standardizing internal representations on canonical Watt-hours (Wh).

Module: promptgreen/engine/thermodynamics.py

5. Anti-Greenwashing Carbon Debt Engine

Deducts wall-clock CPU optimizer compute cost from gross inference savings. When execution overhead exceeds savings (e.g. short queries), the system records negative net energy and triggers a Carbon Debt alert.

Formula: ΔE_net = ΔE_gross - E_local_cpu

6. Conservative Green Model Router

Advisory routing engine that evaluates prompt complexity, task category (coding, reasoning, sentiment), and safety constraints. Recommends tier downgrades with like-for-like physical energy comparisons while strictly guarding complex tasks.

Module: promptgreen/engine/model_router.py

Section E: Academic Limitations & Anti-Greenwashing Transparency

Defensibility Disclosures

Required Epistemic Disclosures for Academic Viva & Evaluation

  • Estimated vs. Physical Measurement: Datacenter inference energy is calculated using published peer-reviewed hardware profiles (mWh/tok) and Power Usage Effectiveness (PUE = 1.15). Figures represent mathematical models, not physical current-clamp hardware telemetry.
  • CPU Overhead Modeling: Local optimizer energy is estimated based on wall-clock execution time multiplied by a nominal 35.0W CPU package power assumption. It is an engineering parameter, not an on-chip RAPL or NVML sensor reading.
  • Output Token Reduction Prediction: Downstream output token savings are statistical forecasts generated by the Hybrid Token Inflation Predictor; they are labeled as "Predicted" and cannot be known deterministically prior to LLM generation.
  • LLMLingua-2 Neural Fallback: If HuggingFace neural weights for `microsoft/llmlingua-2-xlm-roberta-large-meeting` are not downloaded, Stage 2 automatically switches to a high-speed deterministic lexical compaction fallback.
  • Model Routing is Strictly Advisory: The Green Model Router provides recommendations and comparative energy balance simulations; PromptGreen does not automatically redirect production network requests to external LLM providers.
  • Semantic Similarity Limitations: A high MiniLM cosine similarity score (≥ 0.90) indicates semantic proximity in dense vector space, but does not provide a formal mathematical proof of logical or factual equivalence.
  • Regional Grid Factor Provenance: Grid carbon intensity values are fixed benchmark scenarios (`ILLUSTRATIVE_385` from US EIA; `THESIS_367` project baseline). Custom values are documented as unverified user inputs.
  • Operational Water Footprint Coefficient: Water footprint savings are estimated using an empirical Water Usage Effectiveness factor of 1.8 mL/Wh derived from hyperscale datacenter sustainability reports.
  • Realistic Compression Expectations: Token reduction varies widely depending on prompt fluff (from 0% on dense mathematical proofs up to 35% on conversational fluff). PromptGreen prioritizes semantic safety over aggressive compression targets.
  • Anti-Greenwashing Commitment: Single-query optimizations with net negative savings are logged as "Carbon Debt" and never disguised as environmental benefits.

Stage 2 — LLMLingua-2 Neural Compression

Neural compression evaluated on 10 prompts across 3 modes (30 total records). Data sourced from results/master_v2/neural_compression_benchmark.json. Model: microsoft/llmlingua-2-bert-base-multilingual-cased-meetingbank.

Architecture

  • Type: Extractive token selection (not generative — cannot hallucinate)
  • Base model: Multilingual BERT / XLM-RoBERTa family
  • Inference: CPU-local, zero cloud dependency, zero per-call cost
  • Output: Subset of original tokens — meaning preserved by design
  • Protection layer: Stage 1 masking preserves numbers/negations before compression
  • Safety net: Semantic guardrail (cosine ≥ 0.80) rollbacks unsafe reductions
